# 신한카드 8423 파싱 룰 — 취소 알림 포맷 2종 추가 (2026-09-14)

| 카드사 앱 09월 이용금액 (2026.09.01~09.30, 실적 제외 0) | 318,030원 |

원인 조사를 위해 `raw_notifications_2026.jsonl`의 `com.shcard.smartpay` 알림 145건을 전수 재파싱한 결과,
**취소 알림 포맷 2종이 기존 필터에 걸리지 않아 취소가 차감되지 않고 있었다.**

기존 `shinhancard_8423_cancel_v1`은 `[신한카드(8423)승인 취소]` 리터럴만 처리한다.

## 대상 알림

## 알림 구조

신한 취소 알림은 2026년 기준 **3가지 포맷**이 공존한다.

```
# (A) 기존 — cancel_v1 이 처리 중 (05/18, 06/29, 09/04)
title: [신한카드]
text:  [신한카드(8423)승인 취소] 홍*동
       - 취소금액: 150,000원(일시불)
       - 취소일시: 09/04 20:25
       - 가맹점명: (주)위굴리 구도일주 

       [신한카드 1544-7000]

# (B) 신규 — "승인" 이 빠지고 누적금액 줄이 다시 등장 (09/13)
title: [신한카드]
text:  [신한카드(8423) 취소] 홍*동
       - 취소금액: 160,000원(일시불)
       - 취소일시: 09/13 13:48
       - 가맹점명: 테스트가맹점G
       - 누적금액: 775,666원        ← 5/18에 사라졌던 줄이 취소 알림에는 존재

       [신한카드 1544-7000]

# (C) 매출취소 — 한 줄짜리 별도 포맷 (08/28)
title: [신한카드]
text:  신한카드 (8423)  매출취소  홍*동        7,000원  08/24 테스트가맹점H

       [발신번호 1544-7000]
```

(B)는 `)` 와 `취소` 사이에 공백이 들어가고 `승인` 이 빠진 것이 핵심 차이다.
(C)는 라벨(`취소금액:`/`가맹점명:`)이 아예 없는 공백 정렬 포맷으로, 하나카드의
`hanacard_sales_cancel_v1`과 같은 "매출취소" 계열이다.

## 추가된 필터

**기존 필터는 수정하지 않고 뒤에 덧붙였다.** `CardParser`가 파일 순서대로 첫 매칭을 반환하므로
구 포맷은 `cancel_v1`이, 신 포맷은 아래 두 필터가 받는다. 포맷이 또 바뀌면 v3를 덧붙이면 된다.

### `shinhancard_8423_cancel_v2` (신규)

```json
{
  "title_regex": "\\[신한카드\\]",
  "body_regex": "\\[신한카드\\(8423\\)\\s*취소\\][\\s\\S]*?취소금액:\\s*(?<amount>[0-9,]+)원[\\s\\S]*?가맹점명:\\s*(?<merchant>[^\\r\\n]+)",
  "type": "cancel"
}
```

카드번호 `(8423)`은 리터럴로 고정하고, `승인` 유무와 공백만 `\s*`로 열었다.
오탐은 `취소금액:` / `가맹점명:` 앵커가 막는다.

### `shinhancard_8423_sales_cancel_v1` (신규)

```json
{
  "title_regex": "\\[신한카드\\]",
  "body_regex": "신한카드\\s*\\(8423\\)\\s*매출취소[\\s\\S]*?(?<amount>[0-9,]+)원\\s+\\d{2}/\\d{2}\\s+(?<merchant>[^\\r\\n]+)",
  "type": "cancel"
}
```

라벨이 없으므로 `매출취소` 키워드 + `금액원 MM/DD 가맹점` 의 위치 관계로 잡는다.

## 부수 확인 — `[이마트카드 할인]`은 집계 대상이 아니다

`[이마트카드 할인]` 알림(2026년 14건)은 필터를 만들지 않는 것이 맞다.
**할인 필터가 없는 상태의 9월 합계가 카드사 앱 실적과 정확히 일치**하므로,
카드사 실적에 할인금액은 반영되지 않는다는 것이 데이터로 확인된다.
필터를 만들면 합계가 그만큼 부풀어 오른다.

마찬가지로 `[신한카드승인 거절]`(05/31, 27,070원)도 실제 결제가 아니므로 집계 제외가 맞다.

## 배포

`adb push config/card_filters.json /sdcard/Documents/MyCard/card_filters.json` 후
앱에서 ⋮ → **업데이트**(`UpdateAction.rebuildFromRaw`)로 과거 알림에 소급 적용.

> **배포 절차 정정:** CLAUDE.md에는 `adb push`가 MediaStore row owner를 바꿔 동작하지 않으므로
> `content write --uri …`를 쓰라고 되어 있으나, **현재 코드에는 해당하지 않는다.**
> `CardFilterStore`는 MediaStore가 아니라 `AppStorage.file()`로 경로를 직접 열고
> (`/sdcard/Documents/MyCard/card_filters.json`), 앱이 `MANAGE_EXTERNAL_STORAGE`를 보유한다.
> 실측 결과 `adb push` 후에도 owner가 `u0_a305`(앱)로 유지되며 정상 로드된다.
