## 원인 ① 현대카드 알림 포맷 변경 (2026-08-20~) — 최대 원인, -252,000원

**2026-08-20 10:07 알림부터 현대카드가 카드명 표기 순서를 바꿨다.** 알림 자체는 정상

- `hyundaicard_naver_approval_v1` — `네이버 현대카드 승인` 리터럴. 새 포맷은 `현대 네이버 승인`으로 **어순이 반대**.

## 원인 ② SKT 통신요금 자동납부 룰 부재 — -39,650원 (SK 현대카드)

```
08-12 14:30  자동납부 승인 차*욱님 SKT 08월-**23-2287 39,650원     ← 미파싱
08-23 14:40  자동납부 승인 차*욱님 SK브로드밴드 21,890원            ← 파싱 OK
```

`hyundaicard_autopay_approval_v1`의 body_regex는 merchant를 **`SK브로드밴드` 리터럴로
고정**하고 있어 SKT 통신요금 건이 걸리지 않는다.

주의: 두 자동납부는 **소속 카드가 다르다.**
- `SK브로드밴드` 21,890원 → 카드사 앱상 **네이버 현대카드** (현재 필터도 그렇게 매핑됨, 정상)
- `SKT 08월-**23-2287` 39,650원 → 카드사 앱상 **SK 현대카드**

따라서 새로 만들 룰의 `card_company`는 **`SK 현대카드`** 여야 한다.

### 총액 산식 (중요 — 다른 카드와 다름)

단순 합계는 헤더와 맞지 않는다. 실제로 맞아떨어지는 식은 다음 하나뿐이다.

```
승인 10건 합계                                     217,140
  − 8.22 한국정보통신-쿠팡 취소                     -28,710
--------------------------------------------------------
= 총 이용 금액                                    188,430   ← 헤더와 일치
```

- 즉 **8.5 놀유니버스 취소 2건(합계 -315,400원)은 헤더 총액에 반영되지 않았다.**
  목록에는 표시되지만 8월 총액에서는 빠져 있다.
- 해석: 해당 승인 건이 8월 목록에 없으므로 **전월(7월) 승인분의 취소**로 보인다.
  현대카드는 취소를 원 승인이 속한 실적월에서 차감하는 것으로 추정된다.
  → **사용자 확인 필요**: 놀유니버스 결제(146,700 / 168,700)가 7월 건이 맞는지.

### 대조 시 예상되는 차이 (미리 계산)

`config/card_filters.json`의 `com.hyundaicard.appcard` 필터는 **전부 `approval` 타입이고
`cancel` 타입이 하나도 없다.** 따라서 MyCard는 이 카드의 취소 3건을 **모두 잡지 못한다.**

- MyCard가 승인 10건을 모두 잡았다면 → **217,140원** 표시 예상
- 카드사 앱 188,430원 대비 **+28,710원 과다** (8.22 쿠팡 취소 미반영분)
- 놀유니버스 취소 2건은 카드사 앱 총액에도 없으므로 이 차이에는 영향 없음

즉 **+28,710원 차이가 나오면 그것이 "예상된" 결과**이고, 그 외의 차이가 추가로 있으면
그건 별도 원인(알림 유실·파싱 실패)이다.

### 유의사항

- **7번·8번 투썸플레이스 4,700원 2건은 같은 날·같은 가맹점·같은 금액이다. 사용자가 실제 2건임을 확인했다.**
  MyCard의 Room dedupe는 `(pkg,title,text,bigText)` 동일 + **5초 창**일 때만 걸러낸다.
  두 결제가 5초 안에 연달아 일어났다면 **알림 문구가 완전히 동일해 1건이 유실된다.**
  → 대조 시 이 2건이 모두 잡혔는지 반드시 확인.
- **4번 SK브로드밴드 21,890원(자동납부)** — 7월 조사에서 이 카드의 dedupe 유실 금액이
  정확히 **-21,890원**이었다. 매달 반복되는 동일 문구 자동납부 건이라 DB v3 마이그레이션
  (UNIQUE 인덱스 제거)의 효과를 검증할 수 있는 항목이다. 최우선 확인 대상.
